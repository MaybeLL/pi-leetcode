# 完整刷题流程开发方案

日期：2026-10-08。状态：开发提案，尚未实现。

用户已试用并认可当前工作台交互。本轮保留读题、编辑、结果、笔记及返回 Pi 对话的体验，在现有原型上接通真实练习流程。本文与 [产品设计](product-design.md) 配套；平台接口依据及尚未实测的限制见 [接入调研](platform-integration-research.md)。

## 目标与第一版范围

交付一版用户可以每天使用的产品：选择真实题目 → 阅读和推导 → 编写代码 → 运行样例或自定义输入 → 检查结果 → 按需向 Pi 求助 → 修改 → 正式提交 → 复盘 → 下次恢复或重新练习。

建议首发以 **Go、leetcode.cn** 为验收基线，保留站点适配接口。站点选择是本方案的默认建议，尚不是已经确认的用户偏好；若用户主要使用国际站，将首发适配和验收切换为 leetcode.com。首发不同时承诺两站、多语言的完整兼容性。

第一版包括：

- 题号、链接或 slug 打开题目；题库搜索和难度筛选；最近练习。
- 真实题意、示例、约束、平台语言模板及可编辑的测试输入。
- 账户连接、登录状态检查和重新连接。
- 在线运行与正式提交、真实结果展示、错误恢复。
- 三档主动引导、任意档位按需求助、用户明确要求时 Agent 解题和调试。
- 练习历史、结果对应的代码快照、基础复盘和重新练习。

每日一题和随机题在主流程稳定后补齐。首发不包含本地通用执行器、完整 IDE 补全、多语言承诺、学习路线、自动复习、模拟面试或评测平台。

## 用户实际看到的流程

### 进入和连接

首次 `/leet` 自动初始化目录，选择站点、语言和引导程度，再进入选题。已有用户升级后保留当前代码、笔记和设置，只补充必要的新设置。重复进入优先恢复最近练习，并提供切换题目入口。

题目读取是否允许匿名访问，以对应站点实测结果为准；能读取时允许先读题和编辑，运行或提交前检查连接状态。不能匿名读取时明确显示连接入口。

首版账户连接建议采用浏览器正常登录后，在插件专用隐藏输入界面导入该站点会话凭据。插件验证身份并显示账户名、站点和有效状态；不接管密码、验证码或二次验证。需先验证 Pi 终端隐藏输入及粘贴行为，不能用会把值写入对话历史的普通输入流程替代。

凭据由认证模块使用，独立于练习目录保存，优先考虑操作系统凭据存储；若首版采用私有文件，则目录权限 0700、文件 0600，并明确其不是加密存储。凭据不进入 Agent 上下文、日志、练习记录或 Git。退出登录只清除该账户凭据，保留练习成果。

### 选题和读题

`/leet pick` 提供题号/标题搜索、难度筛选、最近练习及已完成标识；分页读取，显示加载、空结果、离线缓存和失败重试状态。

`/leet open 42`、`/leet open trapping-rain-water` 和题目链接定位到同一题。题号是展示编号，不应直接假定为平台提交所需的内部 ID。跨站链接按站点明确处理，不能静默使用另一站点账户。

读题沿用现有工作台。题意 HTML 转为终端可读内容，保留示例、代码、上下标、列表、表格和图片说明/原始链接；无法准确呈现的图示提供原网页入口。清理终端控制字符。算法标签、官方提示和题解默认折叠，避免选题页面提前暴露核心方法。会员题标记访问限制。

已有实现只恢复，不重新注入模板。原型 Two Sum 的手写题意及 `package main` 模板不直接视为平台版本；升级后原样保留原型练习，首次打开真实题目建立独立记录。

### 编辑和运行

保留当前内置编辑器，新增测试用例编辑入口。首次加载使用平台示例输入，允许用户添加自定义输入；输入格式和参数数量来自题目元数据，不从题意文本猜测。设计类题目按平台操作序列格式传递。

运行前保存并创建不可变快照，包含题目、语言、代码、代码哈希和实际输入。发往平台的代码必须与快照一致，Go 直接采用平台模板和提交形式，不擅自拼接 `main`、测试框架或重复的链表/树定义。

运行时显示“正在发送 → 排队/执行 → 已完成”。用户可以返回代码继续编辑，结果绑定发送时的快照；如果代码随后修改，结果页显示“对应之前的代码版本”。运行中的同一请求不可因快捷键连按重复创建。

结果页区分编译错误、运行错误、超时和样例输出，按平台实际返回展示输入、实际输出、预期输出、标准输出及错误信息。某些自定义输入可能没有参考输出，明确显示“未提供预期值”，不由模型生成一个值冒充平台判定。只有平台提供可靠的逐例映射时才标记每个用例的成败。

### 提交和恢复

`/leet submit` 明确表示向当前站点账户正式提交当前代码，是一次主动操作。保存及快照规则与运行一致；检测登录过期或保存冲突时停止发送，并给出可恢复路径。

提交成功拿到平台 ID 后立即持久化，再轮询判题。显示 Accepted、Wrong Answer、TLE、Runtime Error、Compile Error 等平台真实判定；在线样例通过显示“样例通过”，不称为 Accepted。

请求分成三种失败：

1. 确认尚未发送：修复连接或认证后可以重新发起。
2. 已取得平台 ID：恢复查询同一 ID，不再次提交代码。
3. 可能已发送但未取得 ID：标记“提交状态未知”，提供站点提交历史入口；能可靠关联时恢复查询，无法确认时由用户决定是否再次提交。不得静默重试 POST。

关闭界面或取消轮询表示停止等待，不声称撤销了平台任务。重启后可以恢复已有 ID 的查询。403、登录过期、429 和接口格式变化分别反馈；读取/查询采用有界重试及退避，429 尊重 Retry-After，不自动高频重复操作。

本地等待判题超时表示结果暂未确认，不显示为 TLE；TLE 只能来自平台判定。HTTP 200 中的 GraphQL 错误或无法识别的结果状态也不能转换成成功或空题库。

## Pi 协同：把事实和教学节奏接起来

### 命令与 Agent 共用能力

Extension 命令、工作台动作和 Agent 工具调用同一套练习服务。第一批工具建议为：

| 工具 | 作用 |
| --- | --- |
| `leet_search` / `leet_open` | 查找并打开题目，受相同的切题和未保存处理约束。 |
| `leet_context` | 当前题意、准确文件路径、已保存实现、版本、真实结果和帮助记录。 |
| `leet_run` | 对确定的代码版本和输入发起运行，返回平台事实。 |
| `leet_submit` | 用户明确要求提交时使用，包括明确授权的自动解题流程。 |
| `leet_status` | 查询既有执行记录，不创建新提交。 |
| `leet_set_guidance` | 用户要求调整时改变主动程度。 |
| `leet_review` | 记录或更新本次复盘，保留用户笔记。 |

工具返回结构化结果与简短说明，不返回凭据。题目正文、代码及远端错误输出作为数据传给模型，不作为新的系统指令。

用户说“帮我分析”不修改代码；说“帮我实现并测试”可修改和运行；说“独立完成并提交”可完成整个循环，无需逐次重复确认。自动调试设置明确的连续尝试上限，默认建议 5 次；相同错误无进展、认证失败、限流或预算耗尽时停止并说明原因，不无限运行。

### 主动引导的触发和界面位置

仅把引导档位放进提示词，不能保证工作台操作后 Pi 会主动回应。需增加有限的练习事件：首次打开本次练习、用户表达思路、运行完成、提交完成、请求复盘。

| 档位 | 用户在工作台操作后 |
| --- | --- |
| 自主练习 | 只呈现操作结果，不额外启动模型；用户求助时才进入对话。 |
| 轻度引导 | 新的、有意义的进展可触发一次简短观察；没有新信息就不提示。 |
| 逐步带练 | 打开题目后给一个读题问题，用户回应后推进；运行或提交后围绕结果给下一步引导。 |

首发复用 Pi 原生对话，不实现第二套流式聊天。带练在进入练习等清晰交接点保存位置、结束工作台并交给 Pi；异步结果到达时若用户正在编辑，保留工作台并显示“结果已就绪/可查看引导”，不强行抢焦点。轻度引导在用户回到 Pi 的安全交接点最多补一条相关观察。

事件绑定练习 ID、代码快照和结果 ID；同一事件去重。切题或离开练习后不将旧题结果注入新题上下文；Agent 繁忙时排队，并在交付前重新核对活动练习。模型不可用时刷题仍能继续。

不监听沉默时长来提示。单次求助深度与主动程度独立。提示不默认暴露算法名。复盘时记录用户实际获得的帮助，例如观察提示、关键思路、完整解法、Agent 修改；模型对帮助程度的分类标记为推断，允许用户修正。

## 代码组织和持久化

现有主要耦合点是 `problem.ts` 中的固定演示题、`workspace.ts` 中的固定目录和 `DemoResult`，以及 `extensions/leetcode.ts` 中合在一起的命令、会话和 UI 编排。先抽出领域数据和服务，再接网络，不把 API 请求散落在按键处理里。

建议结构：

```text
src/
  domain/          题目、练习、用例、执行和帮助记录
  platform/        站点适配、HTTP、题目解析和判题映射
  auth/            站点账户凭据及有效性检查
  practice/        打开、保存、运行、提交、恢复和复盘服务
  storage/         文件保存、缓存和 schema 迁移
  coaching/        引导规则、上下文和事件交接
  ui/              选题、工作台、用例和结果界面
extensions/
  leetcode.ts      Pi 命令、工具、生命周期的薄入口
```

领域至少区分 `ProblemKey(site, slug)`、展示题号、平台内部 ID、`PracticeAttempt`、`CodeSnapshot`、`Execution(run | submit)` 和 `HelpRecord`。执行状态、平台判定、用户学习记录分别保存。题库缓存、账户已完成状态和判题查询带站点/账户标识；切换账户不能错误复用另一账户的已解决状态。

每次执行保存题目、语言、代码及输入快照、发送阶段、平台 ID、判定、时间和必要诊断信息。错误响应只存脱敏且有大小上限的内容。断线或退出不能丢失平台 ID。代码编辑产生的新版本不会改写历史结果。

继续用可读文件保存用户产物，第一版不引入数据库。增加存储版本和迁移前备份；迁移失败保留原目录，不清空重建。新练习按站点、题目和练习 ID 分隔；重新练习创建新 attempt，不覆盖旧代码。默认目录和自定义目录都保持支持。

保存冲突保留当前防覆盖行为，并补上重新加载/另存草稿入口。现有进程内队列不足以处理两个 Pi 进程，需增加跨进程写入互斥和持锁后的版本检查；不要把“检查后再写”当作完整的原子并发控制。

## 分阶段交付与验收

| 阶段 | 主要交付 | 完成标准 |
| --- | --- | --- |
| M0 接口验证 | 选定站点、会话连接、题目与模板、运行、提交和查询的最小验证程序 | 在专门测试账户上拿到真实题目、一次运行结果和一次正式判定；记录脱敏响应，确认 Go 模板和测试输入。接口不通先解决此阶段。 |
| M1 真实题库和练习 | 领域模型、原型迁移、选题、读题、模板、恢复 | 用题号/链接打开多种真实题目；搜索分页可用；重复打开不覆盖代码；旧原型成果可找到。 |
| M2 真实运行 | 用例编辑、快照、异步任务、错误和结果页 | 故意错误和正确实现呈现对应的真实结果；自定义输入可运行；结果版本可追溯；断网、限流、重新连接可恢复。 |
| M3 正式提交 | 提交工具/命令、持久化 ID、查询恢复、历史 | 能获得真实 AC/WA 等结果；连按不重复发起；提交后断线/重启恢复同一记录；未知发送结果不自动重发。 |
| M4 教学和复盘 | 练习事件交接、工具闭环、帮助记录、复盘、重新练习 | 三档节奏符合约定；只分析不改代码；明确授权后 Agent 能实现、运行、修复和提交；复盘与历史能恢复。 |
| M5 可用性验收 | 安装升级、真实 TUI、模型协同和异常测试 | 从干净安装走完完整流程；在原型数据上升级无丢失；文档与实际能力一致；真实链路验证通过后作为首个可日常使用版本交付。 |

M0 做一条短路径验证可行性，正式架构在后续阶段落地，避免先完成大量界面后才发现站点不可用。M3 完成后可以日常人工刷题；M4、M5 完成才达到本产品“与 Pi 协同学习”的完整首版标准。

### 验证矩阵

- 题型：数组/字符串、多参数、链表、二叉树、设计类；包含中文、代码块、图片和复杂约束。
- 判题：样例成功、WA、编译错误、运行错误、TLE；平台未返回的结果不虚构。难稳定制造的错误采用脱敏响应契约测试，另保留真实账户验证记录。
- 网络：连接失效、403、429、轮询超时、成功发送后连接断开、进程退出恢复、未知响应 schema。
- 数据：原型迁移、自定义目录、外部编辑、多进程保存、切题时未保存、旧结果对应旧代码、重新练习不覆盖历史。
- 教学：自主档不主动启动模型；轻度提示不泄露完整解法；带练一次一问；请求深度不修改档位；切题后旧事件失效；模型缺席仍可运行提交。
- TUI：中文窄屏、宽屏分栏、编辑中异步结果、焦点恢复、草稿冲突、无参考输出的用例。

普通 CI 使用模拟传输和脱敏响应，避免依赖账户、限流或真实提交。发布前单独执行一次真实站点验收；使用者明确授权测试账户后才发送代码，测试计划本身不发起提交。

## 外部依赖与方案边界

LeetCode 接入不能以“第三方插件能运行”推定本项目已验证成功。将第三方客户端源码作为协议线索，把首发站点账户上的真实验证作为交付门槛。认证、题库字段、判题协议均集中在适配层，遇到挑战页或 schema 变化明确停止并报告。

Pi 适配以实际验证的安装版本为准，先维持 0.87.1 验收基线；不要依据上游最新文档直接调用本地不存在的 API。发布时注明验证范围。

当前确定的是开发方向和阶段验收；站点、首发语言及登录体验在 M0 前按本方案默认值推进或由用户调整。首版交付时间需在 M0 的真实接口验证后估算，避免把认证和平台兼容性的不确定性藏进一个固定工期。
