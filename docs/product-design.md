# pi-leetcode 产品设计

pi-leetcode 在 Pi Coding Agent 中提供统一的 LeetCode 练习流程，帮助用户理解题目、推导算法、编写实现，并提升面试中的独立解题和表达能力。用户选择 Pi 的主动引导程度，随时可以请求更多帮助。

本文记录已经对齐的产品目标。当前开发版已接入中国站题库，并实现运行/提交客户端；真实账户核心判题已通过验收，日常交互与基础教学连续性已实现；更长教学过程仍需验证。下文的完整工作流不代表所有功能已经实现。当前可用范围见 [README](../README.md) 和 [接入验收记录](integration-status.md)。

## 统一练习流程

用户围绕同一道题完成选题、读题、思考、编码、测试、提交和复盘。流程允许跳过或回到任意阶段，不要求用户逐项完成固定问卷。

产品提供一套练习流程，不设置独立的学习模式和练习模式。引导程度影响 Pi 的主动行为，不改变题目、代码、测试和提交能力。

## 首次使用和练习工作区

用户安装插件后，首次执行 `/leet` 时自动创建默认数据目录，直接匿名打开 Two Sum，以轻度引导开始；登录延后到首次运行或提交。用户无需手动创建项目或切换到指定目录。仅安装或加载扩展时不创建练习产物。

默认使用插件管理的练习工作区，允许在设置中指定自己的目录，方便使用 Git 或已有的解题目录。插件源码仓库与用户练习工作区分别管理，练习代码不保存到插件安装目录。

建议目录如下，最终路径和存储格式在实现时确定：

```text
~/.pi/leetcode/
  settings.json
  workspace/
    problems/
    records/
  cache/
```

设置保存语言、站点、引导程度和练习目录。工作区保存题目、解题代码、用例、笔记和练习记录；缓存只保存可重新获取的数据。清理缓存、升级和卸载插件应保留练习成果。

设置提供复制并切换练习目录的入口。更换目录时复制现有练习到一个尚不存在的新目录，避免仅修改路径后旧记录不可见。具体迁移方式在存储设计中确定，应保留原数据直到迁移成功。

工作区可独立于启动 Pi 的目录。插件文件操作使用明确的工作区路径，执行工具明确指定运行目录，并向 Agent 提供准确路径；不能把创建目录或切换会话当作已经改变 Pi 所有工具的工作目录。

## Pi 内的题目工作台

文件负责保存，UI 提供日常练习入口。用户在 Pi 中读题、编辑代码、查看结果和笔记，不需要逐个打开 Markdown 文件。外部编辑器作为用户可选的编辑方式。

选题后所有引导档位均先进入题目工作台，显示题目、当前语言、引导程度及可用操作。用户按 F6 明确开始或继续带练，再进入 Pi 对话；调整引导档位本身不启动对话。支持按题号直接进入，也支持浏览、搜索和筛选。宽终端采用题目与代码分栏，窄终端采用单页切换；具体尺寸和快捷键通过 TUI 原型验证。

| 视图 | 内容和操作 | 返回时保留 |
| --- | --- | --- |
| 做题 | 题目与代码共用一页。默认直接阅读，Enter 开始写代码，编辑时 Esc 返回阅读；宽屏并排，窄屏显示当前操作区域。 | 阅读位置、当前代码、光标和滚动位置。 |
| 测试结果 | 展示输入、预期、实际输出及运行错误，返回代码继续修改。 | 最近结果与选中的用例。 |
| 笔记 | 默认只读查看；Enter 编辑，Esc 返回笔记阅读。 | 草稿、阅读位置和编辑状态。 |

向 Pi 求助时携带当前题目、代码及相关测试结果，用户无需复制粘贴。回答后可回到之前的工作台位置。聊天输入与代码编辑有清晰的焦点区分。可点击页签直接切页；F1 做题、F3 结果、F4 笔记直接操作，不再设置独立的 F2 代码页或页签导航模式。三个页面的阅读态均支持 ←/→ 循环切页，↑↓ / PgUp / PgDn 滚动当前内容。题目或笔记中 Enter 开始编辑，编辑时 Enter 换行、左右键移动光标，Esc 返回当前页阅读。结果页用 Shift+←/→ 切用例，保留普通左右键切页。结果或笔记阅读时 Esc 返回题目阅读，题目阅读时 Esc 保存返回 Pi。编辑区 Tab 缩进、Shift+Tab 减少行首缩进。当前操作区使用反色标题与 ▸ 标记；已选页签使用较弱的 ● 标记。状态与操作分区，提示跟随焦点，核心操作始终可见。

离开编辑、测试和提交时必须明确处理未保存代码，避免结果对应旧版本而用户不知情。异步操作显示当前任务及执行状态，失败结果可再次查看并重试；关闭结果界面不应被解释为后台任务已取消。

重新打开题目恢复已有实现。重新练习时建立新的练习记录并保留旧实现。提交保存对应的代码快照，后续编辑不改变历史判题结果所属的版本。

Pi 的 Markdown、滚动、编辑组件及自定义界面能力见 [终端 UI 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/tui.md)。原型已实现分栏、窄屏切换、保存后求助和通过 `/leet` 返回；真实模型的教学效果和长期练习体验仍需试用验证。

选题窗口同样区分焦点与选择：当前搜索框、筛选项或列表行使用反色加粗与 ▸，已应用的筛选用 ✓，离开列表后保留的选中行用 ●。底部说明当前操作区域及按键含义；筛选项和快捷键组合在窄屏完整换行，不靠截断隐藏操作。

## 主动引导程度

设置名称为“引导程度”，提供三个档位。首次练习时选择，默认选项为“轻度引导”。后续练习沿用上次选择，进入题目时显示当前档位并允许修改，不必每次弹出选择框。

| 档位 | Pi 的默认行为 |
| --- | --- |
| 自主练习 | 展示题目、测试和提交结果，等待用户主动求助。 |
| 轻度引导 | 在用户表达思路、请求测试或完成提交等节点，视进展给出一个简短的观察或问题。 |
| 逐步带练 | 主动组织读题、推导、实现和复盘，每次推进一个关键点，等待用户回应。 |

用户可以在练习中通过设置或自然语言调整程度，例如“接下来让我自己想”或“带我一步步推导”。切换保留当前题目、代码、测试结果及已获得的帮助。

Pi 依据对话和用户操作提供引导。安静思考和等待时间不代表用户卡住，不触发催促或提示。外部编辑器中文件发生变化，也不意味着 Pi 应自动发起对话；具体接入事件待实现设计确定。

## 用户主动求助

主动引导程度与本次求助的深度分别处理。所有档位都支持用户请求观察提示、思路分析、错误定位、伪代码、完整讲解或 Agent 示范解题。

用户的当前请求决定本次回应范围。例如“只检查复杂度”只得到复杂度反馈；“给一点提示，别告诉我算法”得到有限提示；“独立完成并讲解”允许 Pi 编写、测试和修复解法。

回应一次求助不会自动改变引导程度。自主练习中获得提示后，Pi 继续等待；只有用户表达调整意图时才改变后续主动行为。

## 引导内容和节奏

每次引导推进一个关键点，提出问题后等待用户回应。Pi 根据用户已有理解调整内容：掌握了基础方法就讨论正确性、边界和复杂度；出现误解则围绕具体误解展开。调整帮助内容时保持用户选择的主动程度。

提示长度不能代表泄露程度。直接给出“双指针”或“单调栈”可能已经揭示核心解法，轻度引导应优先指出值得观察的关系、约束或重复计算。逐步带练也优先帮助用户推导，完整解法或代写代码由用户表达需求后提供。

以用户提出 Two Sum 的双层循环方案为例：

| 档位 | 反馈示例 |
| --- | --- |
| 自主练习 | 等待用户提出问题或继续操作。 |
| 轻度引导 | “内层循环每次都在寻找什么？这部分工作能复用吗？” |
| 逐步带练 | “先估算这个方案的复杂度。结合输入规模，你觉得够用吗？”用户回答后再讨论优化方向。 |

轻度引导不要求每个节点都发言，也不重复已经给过的提示。反馈应与当前进展相关，避免持续打断用户。

## 测试提交和复盘

测试和提交展示真实执行结果，区分本地测试、线上运行与正式提交。本地样例通过不能显示为 Accepted；平台不可用或执行失败应报告实际状态。

测试失败后，自主练习展示结果并等待求助；轻度引导可给一个有针对性的观察；逐步带练可以引导手动推演反例，区分思路错误、实现错误和复杂度问题。自动修改解题代码需要用户提出相应请求。

复盘遵循当前引导程度：自主练习由用户请求，轻度引导简短邀请用户总结，逐步带练主动讨论推导、正确性、复杂度和变式。平台判题结果与学习进展分别记录，不把 Accepted 自动解释为已经掌握。

练习记录至少保留题目、代码、测试与提交结果、实际获得的帮助及复盘笔记。主动引导档位不能直接推断独立完成程度；复习应参考用户是否获得关键思路、完整解法或 Agent 代写等实际帮助。

## 与 Pi 的协同

计划将 Extension 和教学 Skill 打包分发。Extension 提供题目、工作区、执行结果、练习状态和交互入口；Skill 提供教学流程与提示原则；Pi Agent 结合用户表达和当前代码进行讲解，并调用执行工具获取事实。

命令与自然语言使用同一套能力。恢复练习时向 Pi 提供当前题目、引导程度、代码路径、最近执行结果、已获得的帮助及当前进展，避免恢复会话后重复提问或改变引导程度。

Pi 的工具、命令、上下文和会话能力见 [Extension 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)，教学指引的承载方式见 [Skill 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md)，联合分发方式见 [Package 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md)。具体 API 和兼容版本在实现前核对。

## 第一版范围和待定事项

第一版围绕自动初始化、题目工作台、选题、引导设置、按需求助、测试、提交和基本复盘建立闭环。入口为 `/leet`，已有命令草案为 `/leet pick`、`/leet open`、`/leet test`、`/leet hint`、`/leet submit`；设置与复盘的命令语法尚未确定，不增加学习和练习模式切换命令。

模拟面试、完整学习路线、自动复习排程和 Agent benchmark 留待后续设计。TypeScript Extension 加教学 Skill 是实现方向；Go 是首个解题语言的提议，仍需确认。LeetCode 站点选择、认证、题目读取、运行提交接入、测试覆盖范围和存储格式尚未确定。优先接入线上运行和判题是当前方向，可行性需验证，本地运行适配随后设计。

原型的下一步是试用并调整交互，然后确定平台接入接口。目录迁移、重新练习版本管理、真实测试提交和完整复盘尚未实现。原型仅有 Go 演示题，测试结果是明确标识的固定 fixture，不能作为代码正确性的证据。

## 行为验收场景

1. 首次练习显示三个引导选项，默认轻度引导；后续沿用最近选择并可修改。
2. 自主练习中测试失败时，Pi 展示执行结果，不主动分析解法、修改代码或升级引导程度。
3. 自主练习中用户请求一个提示，Pi 提供有限帮助，之后继续等待用户。
4. 轻度引导中用户提出暴力方案，Pi 给出一个相关观察或问题，不直接倾倒完整优化解法。
5. 逐步带练中 Pi 提出一个推导问题并等待回答，不因等待时间继续输出提示。
6. 任意档位下用户只请求复杂度分析，Pi 保持回应范围；用户请求完整解法时可以提供。
7. 用户要求“接下来让我自己想”后，Pi 调整主动程度，保留题目、代码和历史帮助记录。
8. 本地测试通过与正式提交 Accepted 显示为不同结果；学习记录保留实际帮助程度。
9. 用户未创建练习项目时，首次执行 `/leet` 自动创建默认工作区并进入首次设置；重复使用恢复已有数据。
10. 从其他项目启动 Pi 时，练习文件及执行任务仍使用选定的练习工作区。
11. 用户在工作台读题、编辑和查看结果，无需手动打开 Markdown；窄终端可访问同样的核心操作。
12. 用户求助后返回工作台，题目阅读位置、代码及编辑位置保留，聊天输入和代码输入不会混淆。
13. 重新打开题目保留实现，重新练习保留旧版本；结果能对应到实际运行或提交的代码版本。
14. 清理缓存不删除代码、笔记或练习记录；迁移目录成功后可恢复原练习。
